# foodshare-quadlet

Quadlet validation and hygiene for Podman.

The estate runs on Podman with systemd units generated by Quadlet — the
`.container` files that `podman-systemd.unit` turns into services. A
unit with a mistake in it does not fail loudly: it deploys nothing, or
it deploys something that cannot start, and the symptom shows up
somewhere else entirely.

This checks the units before they get there.

## What it checks

| Check | What it catches |
| --- | --- |
| Absolute `/Users/` volume | A laptop path baked into a unit that runs on a server |
| Transcript leakage | Text from an assistant transcript that ended up in a unit |
| `Image=` present | A unit that would start nothing |
| `HealthCmd=` present | A unit with no way to tell whether it is working |

Each failure carries a code — `ValidationError`, `FileReadError`,
`FileNotFound` — and a suggestion, so a CI job can report what to fix
rather than only that something is wrong.

## Usage

```bash
foodshare-quadlet                        # every .container file below the current directory
foodshare-quadlet quadlet/generated      # a directory of units
foodshare-quadlet path/to/unit.container # one file
```

The exit code is the verdict: zero when every unit passed.

## Where the units are

The backend generates its units from the compose file
(`scripts/generate-systemd-units.ts`) and installs them from CI
(`scripts/install-systemd-units.ts`). The units are written to
`quadlet/generated/`, and this is the tool that says whether they are
sound.

The web repository has its own units, mirrored under `.github/quadlet/`
for CI visibility, and checks them with the same rules.
